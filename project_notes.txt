AWS SECURE LANDING ZONE - TERRAFORM PROJECT NOTES
===================================================

ΤΕΧΝΟΛΟΓΙΑ: Terraform (Infrastructure as Code)
CLOUD: Amazon Web Services (AWS)
REGION: eu-west-1 (Ireland)

---

ΤΙ ΕΙΝΑΙ ΤΟ TERRAFORM;
------------------------
Το Terraform είναι εργαλείο που σου επιτρέπει να γράφεις κώδικα (αρχεία .tf)
για να δημιουργείς και διαχειρίζεσαι cloud resources (servers, networks, databases κλπ).
Αντί να κάνεις κλικ στο AWS Console, γράφεις κώδικα και το Terraform τα φτιάχνει αυτόματα.

Εντολές:
- terraform plan  → δείχνει τι ΘΕΛΕΙ να κάνει (χωρίς να κάνει τίποτα)
- terraform apply → εκτελεί τις αλλαγές στο AWS


---

ΑΡΧΕΙΟ 1: providers.tf
------------------------
ΣΚΟΠΟΣ: Λέει στο Terraform ποιο cloud χρησιμοποιούμε και σε ποια region.

resource που δημιουργήθηκε: ΚΑΝΕΝΑ - μόνο ρύθμιση

κώδικας:
  terraform {
    required_providers {
      aws = {
        source  = "hashicorp/aws"
        version = "~> 5.0"
      }
    }
  }

  provider "aws" {
    region = "eu-west-1"
  }


---

ΑΡΧΕΙΟ 2: vpc.tf
-----------------
ΣΚΟΠΟΣ: Δημιουργεί το VPC (Virtual Private Cloud).

ΤΙ ΕΙΝΑΙ VPC: Ένα απομονωμένο ιδιωτικό δίκτυο μέσα στο AWS.
Σκέψου το σαν ένα κτίριο με τους δικούς του τοίχους - τίποτα δεν μπαίνει/βγαίνει
χωρίς να το ορίσεις εσύ.

CIDR Block 10.0.0.0/16: Το εύρος των διευθύνσεων IP που μπορούμε να χρησιμοποιήσουμε.
/16 σημαίνει ~65.000 διαθέσιμες IP διευθύνσεις.

AWS Resource ID που δημιουργήθηκε: vpc-0ae65918d33ba3475

κώδικας:
  resource "aws_vpc" "main" {
    cidr_block           = "10.0.0.0/16"
    enable_dns_support   = true
    enable_dns_hostnames = true
    tags = {
      Name = "secure-landing-zone-vpc"
    }
  }


---

ΑΡΧΕΙΟ 3: subnets.tf
----------------------
ΣΚΟΠΟΣ: Δημιουργεί 2 subnets μέσα στο VPC.

ΤΙ ΕΙΝΑΙ SUBNET: Υποδίκτυο μέσα στο VPC. Σαν "δωμάτια" μέσα στο κτίριο (VPC).

PUBLIC SUBNET (10.0.1.0/24):
- Έχει πρόσβαση στο internet
- Εδώ θα μπαίνουν resources που πρέπει να είναι προσβάσιμα από έξω
  (π.χ. web servers, load balancers)
- AWS Resource ID: subnet-008a80c693198a029

PRIVATE SUBNET (10.0.2.0/24):
- ΔΕΝ έχει άμεση πρόσβαση στο internet
- Εδώ θα μπαίνουν resources που πρέπει να είναι κρυφά
  (π.χ. databases, application servers)
- AWS Resource ID: subnet-01568268ee9bae8d2

κώδικας:
  resource "aws_subnet" "public" {
    vpc_id            = aws_vpc.main.id
    cidr_block        = "10.0.1.0/24"
    availability_zone = "eu-west-1a"
    tags = { Name = "public-subnet" }
  }

  resource "aws_subnet" "private" {
    vpc_id            = aws_vpc.main.id
    cidr_block        = "10.0.2.0/24"
    availability_zone = "eu-west-1a"
    tags = { Name = "private-subnet" }
  }


---

ΑΡΧΕΙΟ 4: internet_gateway.tf
-------------------------------
ΣΚΟΠΟΣ: Δημιουργεί το Internet Gateway και το συνδέει στο VPC.

ΤΙ ΕΙΝΑΙ INTERNET GATEWAY (IGW): Η "εξώπορτα" του VPC προς το internet.
Χωρίς IGW, κανένα resource μέσα στο VPC δεν μπορεί να επικοινωνήσει με το internet.
Το IGW συνδέεται στο VPC (όχι στα subnets).

AWS Resource ID που δημιουργήθηκε: igw-0ec216876420a944a

κώδικας:
  resource "aws_internet_gateway" "main" {
    vpc_id = aws_vpc.main.id

    tags = {
      Name = "secure-landing-zone-igw"
    }
  }


---

ΑΡΧΕΙΟ 5: route_tables.tf (ΕΠΟΜΕΝΟ ΒΗΜΑ)
------------------------------------------
ΣΚΟΠΟΣ: Δημιουργεί Route Table για το public subnet.

ΤΙ ΕΙΝΑΙ ROUTE TABLE: Ο "τροχονόμος" του δικτύου. Λέει στο traffic πού να πάει.

Θα περιέχει:
1. aws_route_table - το ίδιο το Route Table με rule:
   "Όλο το internet traffic (0.0.0.0/0) πήγαινε στο IGW"

2. aws_route_table_association - "κολλάει" το Route Table στο public subnet

ΓΙΑΤΙ ΜΟΝΟ ΓΙΑ PUBLIC:
- Public subnet → χρειάζεται route προς internet → Route Table με IGW
- Private subnet → ΔΕΝ θέλουμε internet access → δεν του δίνουμε route προς IGW


---

ΑΡΧΙΤΕΚΤΟΝΙΚΗ (BIG PICTURE)
==============================

Internet
   |
   | (traffic)
   |
Internet Gateway (igw-0ec216876420a944a)
   |
   | (συνδεδεμένο στο)
   |
VPC 10.0.0.0/16 (vpc-0ae65918d33ba3475)
   |
   |--- Public Subnet 10.0.1.0/24  ← Route Table → IGW → Internet ✅
   |
   |--- Private Subnet 10.0.2.0/24 ← Κανένα route προς internet ❌ (σκόπιμα)


---

ΓΙΑΤΙ ΑΥΤΗ Η ΑΡΧΙΤΕΚΤΟΝΙΚΗ;
==============================
Αυτό είναι το βασικό pattern ασφαλείας για cloud:
- Ό,τι πρέπει να είναι δημόσιο → public subnet
- Ό,τι πρέπει να είναι ασφαλές → private subnet
- Ο IGW ελέγχει ΠΟΙΟΣ μπορεί να επικοινωνήσει με το internet
